## 问题

SFT 已经能让模型学会"正确回答"了，为什么还要 RLHF？DPO 号称省掉奖励模型，它真的能替代 PPO 吗？

## 一句话回答

**SFT 教模型"模仿"，RLHF 教模型"取舍"。** SFT 只能在有标准答案的数据上学习，而人类的偏好往往是**相对的**（A 比 B 好）而非绝对的。DPO 把偏好优化简化成分类问题，省掉了奖励模型，但也因此丢掉了在线探索的能力。

## 展开

### 1. SFT 的天花板

SFT 的损失函数是 next-token 的交叉熵 —— 它在问"**这个 token 出现的概率能不能更高**"。

问题在于：

- **只有正样本** —— 没有"这样回答不好"的信号
- **模仿而非判断** —— 模型学会复现参考答案的分布，学不会在多个合理答案中选最优
- **数据瓶颈** —— 高质量标注贵，且越到后期边际收益越低

更根本的：**很多任务没有唯一正确答案**。写一段代码、解释一个概念，好答案是一整个分布，SFT 无法表达"这个比那个好"。

### 2. RLHF 的三段式

```
SFT  →  训练奖励模型（RM）  →  PPO 优化策略
```

关键在第二步：**用人类偏好对训练奖励模型**（同样输入下，A 优于 B），再用 RM 给策略打分。

PPO 阶段则是**在线**的 —— 策略生成新回复、RM 打分、更新 —— 模型能探索到 SFT 数据里没有的答案。

代价也很明显：训练 RM + 维护 4 个模型（策略、参考、RM、价值网络），工程复杂度高、不稳定、对超参敏感。

### 3. DPO 做了什么

DPO 的洞察：**奖励模型和最优策略之间存在解析关系**，可以把 RM 直接代掉，得到一个只用偏好对的损失函数。

```python
# 简化形式
loss = -log σ( β · [ log π_θ(y_w|x) - log π_ref(y_w|x) ]
              - β · [ log π_θ(y_l|x) - log π_ref(y_l|x) ] )
```

直觉：**提高好回答的相对概率，压低坏回答的相对概率**，同时用参考模型 `π_ref` 拉住，防止偏离太远。

好处：只需一个偏好数据集，训练稳定，超参少。

### 4. DPO 的局限

| 局限 | 原因 |
|------|------|
| **无在线探索** | 全程用离线偏好数据，模型无法生成新样本再评估 |
| **分布偏移** | 训练越久，策略越偏离数据分布，偏好对的参考价值下降 |
| **无法用密集奖励** | 只能比较同一 prompt 下的两个答案，做不了过程奖励（PRM） |
| **对数据质量敏感** | 偏好对噪声直接传导到梯度 |

**一句话**：DPO 是"用现成偏好数据做离线对齐"，PPO 是"边生成边评估的在线优化"。数据覆盖足够好时 DPO 很香；需要探索、需要过程奖励、需要持续迭代时，还是得回到 PPO 系（或 GRPO 这类变体）。

### 5. 现在的主流拼法

工业界常见路线：

```
预训练 → SFT（冷启动）→ 偏好优化（DPO/GRPO）→ 人工评估 → 迭代
```

对推理类任务，**GRPO** 因为不需要价值网络、可以用规则化奖励（答案对不对），成了新宠。

## 面试延伸

- **DPO 里 β 的作用是什么？** 控制偏离参考模型的强度 —— β 越大越保守
- **为什么 DPO 需要参考模型？** 它是正则项，防止模型为了刷偏好分数而把输出分布搞崩（reward hacking 的软约束）
- **SFT 数据越多越好吗？** 不是。质量 > 数量，早期少量高质量 SFT 往往优于海量噪声数据
